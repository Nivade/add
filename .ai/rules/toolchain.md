# Toolchain and Monorepo

npm workspaces at the root: `backend`, `mobile`, `packages/*`. Work from the
repo root — `.git`, `.ai/rules` and `.claude` all anchor there, and most changes
cross a workspace boundary. Root scripts exist so nothing needs a manual `cd`.

## One lockfile, installed from the root

`npm install` runs at the root and nowhere else. A second `package-lock.json`
inside a workspace is not a backup — npm ignores it, the two drift, and the tree
that is actually installed stops matching the one CI resolves. A stale partial
tree in the root `node_modules` also makes npm nest what should hoist, so a
consolidation is `rm -rf node_modules */node_modules package-lock.json` and one
install, never an incremental fix.

CI checks out the repo root, so every workflow needs
`defaults.run.working-directory: backend` and root-relative paths in any `with:`
block — `hashFiles('backend/composer.lock')`, not `composer.lock`.

Every root script routes through Sail — `artisan`, `composer`, `test`,
`test:serial`, `test:impact`, `lint`, `stan`, `types:generate`. The container is
where PHP 8.5 and the real Redis live, so it is the environment the code is
written against. `npm run artisan:host` and `npm run test:host` are the opt-outs
for SQLite-only work when the containers are down.

`boost:update` is the one exception and stays on the host: Boost walks up from
the Laravel base path to find `.claude/`, which is above the mount.

## React Native and Inertia React share less than it looks

**Shared:** types, domain logic, time math, design tokens. **Not shared:**
components (RN renders native views, Inertia renders DOM) and routing (Inertia
is server-driven; RN talks to `routes/api.php`). Every screen is written twice.
Do not attempt a shared component layer.

`packages/shared` stays dependency-free and platform-free — no `react`, no
`react-native`, no Node built-ins, no browser globals. It is imported by both
frontends.

## Redis only exists inside Compose

`REDIS_HOST=redis` is a Compose network hostname; the host cannot resolve it, so
`php artisan queue:work` on the host fails where `sail artisan queue:work`
works. Host `php artisan` is fine for SQLite-only work, and `php artisan test`
is fine because `phpunit.xml` pins `CACHE_STORE=array`, `QUEUE_CONNECTION=sync`,
`SESSION_DRIVER=array`.

## The container mounts three paths, not one

Sail mounts `backend/` at `/var/www/html`, so anything the app reaches above its
own base path is invisible by default. Two writes need it:
`base_path('../packages/shared/src')` for the generated TypeScript, and the
`backend/.ai` symlink, which points at `../.ai`. `compose.yaml` therefore also
mounts `../packages` at `/var/www/packages` and `../.ai` at `/var/www/.ai`, so
both resolve to the same files the host sees. Drop either mount and
`types:generate` writes into the container and disappears on the next rebuild.

## PHP is 8.5 in both places

`compose.yaml` builds `vendor/laravel/sail/runtimes/8.5` as `sail-8.5/app`, and
`composer.json` requires `^8.5`. Changing the runtime is a rebuild
(`sail build`), not a restart — a stale image keeps serving the old PHP while
`composer.json` claims otherwise.

## compose.yaml is hand-edited

Generated by `devtools:install`, then edited to drop the `mysql` service, its
`depends_on` entry and the `sail-mysql` volume. `devtools:sync` would revert
that, so we do not run sync. Removing a service means removing its named volume
**and** that volume's `driver: local` line; orphaning one breaks the YAML in a
way the error does not point at. Validate with `docker compose config --quiet`.

## Ports are offset to coexist with the sibling repos

tabellio uses 6380 / 1026 / 8026 / 5174, first-move 6381 / 1027 / 8027 / 5175.
This repo uses 6382 / 1028 / 8028 / 5176, `COMPOSE_PROJECT_NAME=add`.

## Sail writes files as uid 1337 unless WWWUSER is pinned

`npm run` executes scripts with `sh`, where Sail's `$UID` fallback is unset, so
generated files land owned by 1337 and the host cannot delete them.
`WWWUSER=1000` / `WWWGROUP=1000` are pinned in `.env` and `.env.example` for
this reason.

## Vite serves through Traefik

`vite.traefik.js` matches the routers in `compose.yaml`: TLS terminates at
`vite.add.nvade.dev`, so the dev server's `origin` must be that https host or
every asset is blocked as mixed content and HMR dies.

## Dev-only packages must not be registered unconditionally

`spatie/laravel-typescript-transformer`, `laravel/boost` and `nvade/devtools`
are `require-dev`. `App\Providers\TypeScriptTransformerServiceProvider` extends
a class from the first of them, so `bootstrap/providers.php` filters it out when
that class is absent. Without the guard, `composer install --no-dev` fatals on
boot.

## Pint does not run Rector

`npm run lint` runs Pint only. Rector lives in `composer refactor` and nothing
else triggers it, so its rewrites accumulate until they land, unrelated, in
someone else's diff. Run `composer refactor:check` before committing and land
its changes as their own commit.

`rector.php` takes the shared `nvade/devtools` preset and adds three things:
`LaravelSetList::LARAVEL_130`, whose attribute rules are what actually enforce
"prefer attributes over class properties"; a skip for `app/Support/Ai/Prompts.php`,
where a byte change moves `AiRequest::cacheKey()`; and skips for `ThrowIfRector`,
`ThrowWithPreviousExceptionRector` and `AppToResolveRector`, each commented in
place.
